# UI 與 Canvas 視覺開發與驗證強制守則 (UI & Canvas Verification Rules)

凡在本專案進行任何涉及 Canvas 模擬、前端排版、動畫或圖形渲染的修改，必須嚴格遵守以下強制工程標準：

---

## 1. 視覺驗證前置條件（嚴禁空口宣稱完成）
- **禁止僅憑「Console 零報錯」宣稱驗證通過**：
  - HTML5 Canvas 與 SVG 操作即使像素繪製在錯誤座標或重疊，瀏覽器控制台亦不會報錯。
  - 在向使用者宣稱「完成」前，**必須啟動 Browser 截圖並主動進行像素級視檢**（檢查：線條接縫、文字重疊、元件邊界、圖示遮擋）。
- **非 100% 視覺確認前之回報措辭**：
  - 僅能說明「邏輯與程式碼已編寫完成，正在進行視覺畫面核對」，嚴禁使用「已完美修復」、「已 100% 完成」等盲目保證。

---

## 2. Canvas High-DPI 與像素縮放標準（DPR Compatibility）
- **嚴禁在主畫布直接調用 `ctx.putImageData`**：
  - 原生 `putImageData` 會略過 Canvas 的縮放矩陣（`ctx.setTransform`），在 Windows 縮放螢幕（DPR 1.25x / 1.5x / 2.0x）下會導致波場、圖像嚴重位移與縮小。
  - **唯一核准標準**：所有像素級點陣運算必須透過 `getOffscreen(w, h)` 寫入離屏畫布，再經由 `ctx.drawImage(off.canvas, ...)` 繪製回主畫布，以確保在所有解析度與縮放比下精準對齊。

---

## 3. 畫布文字防碰撞排版標準（No Magic Number Overlaps）
- **禁止寫死接近的 Y 軸常數**：
  - 畫布底部的多行說明文字，必須定義基礎行高與動態索引（例如 `const lineH = 18; const y = baseY + index * lineH;`）或明確規劃分層間距（至少留足 16–20px 行距）。
- **保留畫布邊界 Margin**：
  - 繪圖區域底端至文字區域必須預留至少 20px 緩衝區，避免圖樣與文字穿透。

---

## 4. 自動化檢查腳本輔助
- 每次提交或宣告完成前，應自動運行檢查腳本確認：
  1. 程式庫內無任何未封裝的 `putImageData` 孤立調用。
  2. 題庫資料格式與引用資源（圖片、截圖路徑）均存在且非空。
